# Echo Voice web: implementation and qualification

This document maps every section of the attached product plan to the delivered local web implementation. **Implemented** means there is working application code for the workflow; it does not mean every browser, microphone, meeting platform, or model has been qualified. **Limited** identifies an explicit boundary. **Unavailable** identifies a feature that this version does not provide. This is not a claim of full desktop feature parity.

The user amended the online-meeting requirement: connect a calendar and join a meeting through a local recording guest, rather than manually capture a meeting tab. The final application uses **Dioxus 0.7/Rust for the browser interface, Axum REST APIs, SQLite and local audio files**, with small JavaScript modules for browser media and local Transformers.js inference.

## What “local” means

- The application opens in a browser, but a local server must run on the computer. There is no required desktop application or browser extension. Running the server and optional meeting guest still requires local runtime setup.
- Meeting metadata, transcripts, notes, vocabulary, and original recording chunks live in `ECHO_DATA_DIR` (default `.echo-data` in the application directory). Browser microphone recording periodically uploads chunks to that server on the same machine.
- Speech models download into the browser's Cache Storage and run in a browser worker. Clearing site data can remove models; it does not delete the local server's meeting library. Browser cache eviction can require a new download.
- Notes default to an explicitly configured Ollama service on loopback, which maintains its own downloaded model files. ChatGPT notes are an optional cloud choice through the official Codex CLI 0.160.0 app-server and managed ChatGPT OAuth. Each cloud generation requires consent to send the whole active transcript, including speaker labels, to OpenAI. Highlight filters do not narrow that scope. Audio and speech recognition remain local; providers never fall back automatically.
- The ChatGPT connection uses an eligible plan's Codex allowance, not a general ChatGPT token pool or OpenAI API credits. Echo does not automatically redeem credits or switch billing methods. The helper keeps account state in its private `CODEX_HOME`, `<ECHO_DATA_DIR>/chatgpt/`. Supported library backups exclude those credentials; full-folder copies can contain them.
- Calendar authorization and joining Google Meet necessarily contact Google. This connection shares calendar/account metadata and joins a meeting as a visible participant; it is separate from local storage and inference. No meeting content is submitted to Google as an inference API request.
- Model downloads need a network connection initially. Local capture/review and already-downloaded models can work without an inference network connection. ChatGPT notes and remote online meetings require internet connectivity. See [ChatGPT setup and qualification](chatgpt.md).

## Practical qualification limits

- **Microphone:** use a secure context (`localhost` or HTTPS), grant access explicitly, keep the workspace open, and test a short recording on the actual browser/device before relying on it. Browser suspension, tab termination, device loss, or operating-system failure can interrupt capture.
- **Speech:** imported audio is bounded to 500 MB by the upload interface; speech decoding rejects audio over 512 MB or two hours. It decodes/resamples in the browser, so RAM matters. Download the exact selected model before transcribing. Full Large V3 needs the [optional native runtime](native-speech.md); Turbo and speaker grouping remain in-browser. Supported catalog entries are in `web/models.js`.
- **Notes:** local generation requires a compatible loopback Ollama service and downloaded model. Optional ChatGPT generation requires the pinned official Codex 0.160.0 helper, eligible account, network access, and consent for each request. The source package lists the helper as an optional npm dependency; `scripts/package.mjs` bundles the Linux x64 helper/license when available. Live ChatGPT OAuth, cloud model access/generation, and account usage have not been tested here; checks use fixtures. See [setup and qualification](chatgpt.md). Output is a draft. Evidence-link validation and provenance help review it but do not remove the need to verify decisions/commitments.
- **Calendar/guest:** real Google Cloud credentials and user consent are required. Local guest operation also requires the documented Linux/PulseAudio/FFmpeg/Playwright prerequisites and meeting-host admission. No Fireflies account, hosted bot service, or hidden remote fallback is used. See [integrations.md](integrations.md).
- **Backups:** meeting JSON is portable text/history/metadata. For audio too, use Storage's web-library backup within its limits or copy the whole stopped server data directory. Supported archives exclude sign-in credentials; full-folder copies can include them, including `<ECHO_DATA_DIR>/chatgpt/`. Clearing a browser cache is not a server-library backup or deletion operation.

## Verification record

Tests are intentionally separated from external qualification:

- `cargo check -p echo-app` checks Dioxus/Rust types and component compilation; a WASM build checks the browser target.
- Rust backend tests exercise metadata/version preservation, payload validation, path boundaries, duplicate chunks, backup/import, interrupted state and deletion/recovery behavior.
- `npm test` runs recorder/inference failure and cancellation checks, REST tests, and `tests/chatgpt-protocol.test.mjs`. ChatGPT protocol checks use a local helper fixture; they do not sign in or consume real account usage.
- Extension authorization/capture/recovery tests cover validation/authentication/recovery without claiming a successful real Google meeting.
- `tests/review.e2e.mjs` exercises the running Dioxus review interface against real REST writes and original audio on a separate test data directory. It is designed to check corrections, speaker labels/samples, saved moments, note versions, evidence, exports, deletion, browser errors and responsive overflow.

Use the actual command results in the [verification record](verification.md) as the executed-test record. A test listed here is not a claim that a real external account, model download, microphone or online meeting has been exercised in this environment.

**Executed review check, 2026-10-04:** `node tests/review.e2e.mjs` passed against an isolated local Rust server and Chromium, including all eleven workflow groups reported by the script, desktop/mobile screenshots, and zero page or console errors. The recording fixture is generated PCM audio and the transcript/notes are explicitly seeded test records; this check does not claim speech-recognition accuracy or a live meeting connection.
