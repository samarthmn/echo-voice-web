# Echo Voice web architecture

## Intent
A single-user meeting workspace with local storage, local speech recognition, and a professional responsive interface. The uploaded product plan is the baseline, amended by the user's requests for calendar-connected meeting bots and optional ChatGPT notes. Ollama remains the default notes provider. Cloud notes require an explicit provider choice and consent for each generation; there is no cloud database. No design approval gates: the user explicitly requested autonomous implementation.

## Chosen approach
Dioxus 0.7 Rust/WebAssembly components, a Rust Axum same-origin REST server, and SQLite stores metadata; local files store recording chunks. Browser MediaRecorder records room audio. Transformers.js in a web worker downloads Turbo and speaker models into browser Cache Storage and executes locally with WASM. Full Large V3 runs in a server-supervised Node.js CPU helper using the pinned native ONNX checkpoint; its model cache stays in the private data folder. Notes use either loopback-only Ollama or the explicitly selected ChatGPT connection. Calendar OAuth sends calendar metadata to Google; audio/transcript never goes to Google for inference. The optional Google Meet runner is local Python/Playwright/Chromium with PulseAudio and ffmpeg. Other meeting platforms are explicitly unavailable until qualified.

The ChatGPT path uses the official Codex CLI 0.160.0 app-server over stdio. The helper manages ChatGPT OAuth and uses an eligible plan's Codex allowance, not a general ChatGPT token pool or OpenAI API credits. Source builds declare the pinned helper as an optional npm dependency. `scripts/package.mjs` includes the Linux x64 native helper and license when available. See [ChatGPT setup](chatgpt.md) for executable discovery and compatibility requirements.

Alternatives considered: browser-only IndexedDB removes the local server but cannot support the requested autonomous bot; a hosted bot moves recording outside the user's computer. The local server plus optional runner fits the requested control over audio storage and processing. The user explicitly selected Dioxus during implementation; the initial Next.js implementation was replaced with Rust components and APIs.

## Interfaces and ownership
JSON REST objects are the shared contract. `server/src/store.rs` owns SQLite and file storage. `/api/meetings` manages records, uploads, transcript and notes history, moments and exports. `/api/settings`, `/api/vocabulary`, `/api/storage` manage the workspace. `/api/integrations` owns calendar and runner. `server/src/notes.rs` dispatches `/api/notes` generation to the requested provider, validates passage evidence, and stores the producing provider/model plus token counts when reported. `server/src/chatgpt.rs` owns helper lifecycle, account/model status, and cloud generation. Browser worker and hooks own recording and local speech recognition. Components render a warm white canvas, dark ink typography, indigo accents, consistent Lucide icons, quiet transitions, and responsive navigation.

## Reliability and privacy
Save periodic audio chunks independently of speech processing. Preserve earlier transcript and notes versions on edits/regeneration/failure. Recover recording records as interrupted after server restart, never restart recording automatically. Consent is required on recording and bot start. Keep recording controls mounted while navigating. Source loss stops capture with a specific error and preserves uploaded audio. Constrain mutation origins and local provider URLs, validate payloads, bound uploads, and never expose OAuth secrets. Deletion confirms scope. Backups copy supported web-format data; legacy desktop compatibility is not claimed.

ChatGPT generation separately requires explicit cloud consent before sending the whole active transcript, including speaker labels, in bounded excerpts. Highlight filters do not change that scope. Audio remains local. Notes providers and billing methods never fall back automatically; allowance or provider failures preserve existing notes.

Echo assigns the helper a private `CODEX_HOME` at `<ECHO_DATA_DIR>/chatgpt/` and a separate working directory, excludes host OpenAI/Codex credentials from its child environment, and writes managed configuration. It requests ephemeral, read-only threads with no tool/network access in the execution sandbox, validates the returned thread settings, and rejects tool activity. These are application safeguards, not a claim of proven OS-level isolation; the helper still needs network access for OAuth and cloud inference. Supported library backups exclude helper credentials; full data-folder copies can include them.

## Qualification boundaries
ChatGPT integration has fixture-based verification only so far; live OAuth, account eligibility, model access/generation, and account usage have not been tested here. The app-server protocol includes version-sensitive experimental surfaces and is pinned to Codex 0.160.0. Real Google OAuth needs user credentials and browser consent. A meeting bot needs local runner dependencies, meeting-host admission and a live platform compatibility check. Model downloads require access to model hosts. Browser inference speed varies. Speaker diarization, acoustic echo cancellation, seamless microphone switching, and destructive passage/audio redaction must not be presented as verified when unavailable. See [feature coverage](feature-coverage.md), [ChatGPT qualification](chatgpt.md#verification-boundary-and-official-references), and the [verification record](verification.md).

## Verification
Test storage/version isolation, mutation protection, path traversal and URL validation, bad uploads, failed provider calls, calendar state, recording recovery. `npm test` includes ChatGPT app-server protocol fixtures alongside inference, recorder, and REST checks. Build and typecheck. Use Playwright against real REST endpoints for first-use, import, search, edit, bookmark, notes provenance, exports, settings, mobile layout and keyboard navigation. Exercise capture with browser fake audio if available. Keep unsupported external prerequisites visible.
